Install Snug on Windows or Mac

Snug works in a web browser. If you want it as an app on your computer, this page says which file to download, what warning you may see, and how to check that the file is the real one. Downloading needs no account.

  2. Check the download

1. Pick the file

Open Snug's newest release: github.com/DominicsUSE/Claude-apps/releases/latest. Scroll down to Assets. The numbers in the names are the version (for example 0.12.0).

You haveDownload
Windows 10 or 11, and you want Snug in the Start menuSnug-Setup-<version>.exe (the installer)
Windows, and you don't want to install anythingSnug-<version>-portable.exe (runs from wherever you put it)
A Mac (Apple silicon or Intel)Snug-<version>-mac.dmg

Also download the checksum file for your system, SHA256SUMS-windows.txt or SHA256SUMS-mac.txt: step 2 uses it. You don't need the .sig files; the app uses them when it updates itself. Ignore releases of other apps on that page: Snug's are named Snug <version>.

2. Check the download

A checksum is a long code calculated from every byte of a file. If even one byte is different, the code is completely different. Compare the code of the file you downloaded with the line for that file in the checksum file.

On Windows

  1. Open the Start menu, type PowerShell and open Windows PowerShell.
  2. Go to your Downloads folder and calculate the code (use the name of the file you downloaded): 
    cd $HOME\Downloads
Get-FileHash .\Snug-Setup-0.12.0.exe -Algorithm SHA256
  3. Open SHA256SUMS-windows.txt in Notepad. The code under Hash must be the same as the code at the start of the line that ends with the file's name. PowerShell writes capital letters and the file small ones; that difference doesn't matter.

On a Mac

  1. Open Terminal (Applications > Utilities).
  2. Calculate the code (use the name of the file you downloaded): 
    shasum -a 256 ~/Downloads/Snug-0.12.0-mac.dmg
  3. Compare it with the line for that file in SHA256SUMS-mac.txt. Or let the Mac compare for you: 
    cd ~/Downloads && shasum -a 256 -c SHA256SUMS-mac.txt
    It prints the file's name and OK when they match.

If the codes are different, don't open the file. Delete it and download it again from the release page.

What this proves: your file is exactly the file the release lists. It catches a damaged download, or a copy someone changed and passed on through another site or a chat. It can't catch someone who could change the release itself, because the checksum file comes from the same place. The next check covers that.

Optional: check where it was built

Every Snug file on the release page is built by GitHub's own machines from the project's public code, and GitHub records a signed statement of that (a build provenance attestation). With the GitHub command-line tool (it needs a free GitHub account and gh auth login once) you can check it:

gh attestation verify Snug-Setup-0.12.0.exe -R DominicsUSE/Claude-apps

It says Verification succeeded! and names the workflow that built the file (build-snug-windows.yml or build-snug-mac.yml). Anything else means the file was not built there.

3. The warning you may see

Windows: “Windows protected your PC”

Windows SmartScreen shows this for programs it doesn't know yet, with Unknown publisher when the file isn't code-signed. Code signing needs a certificate in the project's name, which Snug doesn't have yet, so for now Snug's Windows files are not signed and you will see this warning. It means Windows doesn't know who made the file. It doesn't mean Windows found something wrong with it.

Once you have checked the file (step 2): choose More info, then Run anyway.

To see whether a file is signed: right-click it, Properties. A signed file has a Digital Signatures tab with the signer's name; an unsigned one has no such tab. Even a signed file can show the warning for a while after a new version comes out, until enough people have downloaded it.

Mac: “Apple could not verify Snug is free of malware”

Apple only stops this message for apps it has checked (“notarized”), which needs a paid Apple developer membership. Snug isn't notarized, so macOS shows this the first time.

  1. Open Snug once and choose Done (or OK) on the message.
  2. Open System Settings > Privacy & Security, scroll down to the message about Snug and choose Open Anyway. Confirm with your password.

On macOS 14 and older you can also Control-click Snug in Applications and choose Open.

4. Install

  • Windows installer: double-click Snug-Setup-<version>.exe. It installs for you only (no administrator needed) and adds Snug to the Start menu and the desktop.
  • Windows portable: put Snug-<version>-portable.exe where you like and double-click it.
  • Mac: open the .dmg and drag Snug to Applications.

The first time, Snug asks where it should run: on this computer, or joining a Snug that someone else runs.

5. Updates, and going back to an older version

Snug updates itself. It downloads the new version from the same release page and installs it only after its checksum matches the release's checksum file (and, once the project switches on update signing, only if that file carries the project's signature). It waits for a quiet moment and never restarts during a call.

Snug never goes back to an older version by itself. Every version stays on the release page: all Snug releases. If a new version breaks something for you:

  1. Tell the project: github.com/DominicsUSE/Claude-apps/issues (needs a GitHub account).
  2. To go back now: download the older version's file from its release, check it as in step 2, and install it over the current one (Windows) or replace Snug in Applications (Mac). Your conversations and settings stay in your data folder. Things the newer version added won't work in the older one.

Updates are required, so an older version updates itself again soon after it starts, unless the project has withdrawn the broken release (marked it as a pre-release). Going back is a way to keep working until a fixed version is out.

Snug is free and open source. The code is at github.com/DominicsUSE/Claude-apps. Security problems: see the project's security policy (SECURITY.md) and report them privately.
